# Учебный Model Registry

Небольшой registry с нуля для домашней работы по MLOps. Он хранит **модель → версии → файл и метаданные**, позволяет найти модель команды, скачать конкретную версию и переключить указатель `production`.

Проект рассчитан на человека, который знает Python и знакомится с HTTP API и БД. Основная реализация — пять небольших файлов Python и SQL-схема. Реальные модели из условия не нужны: демонстрация сама обучает две игрушечные модели без ML-библиотек.

## Быстрый запуск

Нужен Python **3.11–3.14**. Проверено на Python 3.14.2; другие версии здесь не прогонялись. Все команды выполняются из каталога `model-registry`. Docker и внешняя БД не требуются.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn registry.app:app --host 127.0.0.1 --port 8000
```

В Windows активация: `.venv\Scripts\Activate.ps1`; для создания окружения можно использовать `py -3 -m venv .venv`.

Открой [Swagger UI](http://127.0.0.1:8000/docs). Это готовая страница для отправки запросов к API. Для оформления Swagger загружает JS/CSS из CDN; сам API и демонстрация работают без CDN.

Во **втором терминале**, из того же каталога:

```bash
source .venv/bin/activate
python examples/demo.py
```

Пример создаёт отдельную модель при каждом запуске, загружает v1 и v2, сравнивает MAE, переводит `production` на v2, скачивает файл и проверяет SHA-256. Прогноз `y=21` для `x=10` считает клиентский скрипт. Registry только сохраняет и отдаёт файл.

Ожидаемая суть вывода:

```text
2.1. Загружена версия 1, MAE=8.00
2.2. Загружена версия 2, MAE=0.00
3. Production переключён с v1 на v2
4. Файл скачан, SHA-256 совпал; локальный прогноз для x=10: 21.0
```

## Тесты

```bash
python -m pytest -q
```

Проверено: **26 тестовых сценариев проходят** на Python 3.14.2.

Тесты используют временную SQLite-БД и временные файлы. Запущенный сервер не нужен. Проверяются сохранение байтов, конкурентные версии, aliases, валидация, откат ошибки БД, рестарт и повреждение артефакта.

## Как устроен проект

```text
registry/
  app.py          HTTP endpoints: принять запрос и вернуть ответ
  schemas.py      Формат входных/выходных данных и валидация
  db.py           SQL-запросы и транзакции
  schema.sql      Три таблицы, ключи и ограничения
  storage.py      Запись файла, лимит размера и SHA-256
examples/
  demo.py         Два обучения, регистрация, выбор и скачивание
  metadata.json   Пример описания версии
  tiny-model.json Пример файла модели
tests/            Интеграционные тесты API
docs/             Отчёт, API и учебный разбор
```

Начни с [пошагового разбора](docs/walkthrough.md), затем прочитай `schemas.py`, `schema.sql`, `app.py`, `db.py` и `storage.py`. Сначала проследи только загрузку одной версии; затем переходи к aliases и обработке ошибок.

## Данные и ограничения

При старте создаются `data/registry.sqlite3` и `data/artifacts/`. Они сохраняются после перезапуска. `MODEL_REGISTRY_DATA_DIR` позволяет выбрать другой каталог. `demo-output/` содержит исходные примеры и скачанный файл. Эти каталоги исключены из Git.

Это сервис для доверенного локального окружения: без авторизации и разграничения команд. `team` — пространство имён, а не проверка прав. Один артефакт — один непрозрачный файл до 10 MiB. Каталог модели можно заранее упаковать в архив: сервер его не распаковывает. Политики согласования production, автоматический deploy, обучение на сервере и сборка окружения в проект не входят.

Сбой процесса между записью файла и фиксацией БД может оставить бесхозный файл. Файловая система и SQLite не образуют общую транзакцию. Подробности сохранности, восстановления и развития до PostgreSQL/S3 — в [отчёте](docs/report.md).

## Как превратить папку в репозиторий для сдачи

Создай пустой репозиторий на своём GitHub/GitLab. Загружай именно содержимое `model-registry`, без виртуального окружения, БД, файлов моделей и других домашних работ. `.gitignore` уже настроен. После публикации ссылка на репозиторий и `docs/report.md` составят результат задания.
